# Agent Note: DSHC 紧凑导航，不复制 slot 实例

Status: implemented

[English](2026-09-17-dshc-compact-navigation.md) | 中文

## 问题

导航需要在桌面端为阅读留出更多空间，并在窄窗口中保持可用，同时不能在每次打开导航时都调整对话区的尺寸。侧边栏的占用者持有状态和全局事件监听器，因此为覆盖层复制一份 slot 也会复制工作区控件和事件消费者。

## 决策

布局使用 260px 的默认侧边栏，桌面端可在 240–420px 范围内调整宽度。低于 1024px 时，列宽求解器接收已有的零值偏好哨兵，并预留 56px 的图标轨道。打开导航时，同一个侧边栏元素被定位到该网格上方，把实际的抽屉宽度传给占用者，对话区仍保留在显式指定的第二个网格列中。桌面宽度在跨越断点时保持不变；抽屉的展开状态是临时的。

导航是一个非模态的 complementary 区域。打开时焦点移到该区域；在其中按 Escape 会关闭抽屉，除非嵌套的对话框拥有该事件。指针点击遮罩同样会关闭导航。键盘用户仍可自由访问对话区；实现并不声称具备模态焦点隔离。Shell 覆盖层位于抽屉之上。不需要新的 slot、公开值导出、包或服务器操作。

对话区使用 760px 的阅读轴。已有的输入框关系保持为内容宽度加 32px，与 dock 卡片和接管卡片保持对齐，并保留所选的阅读字体。这一几何调整不改变 DSHC 的配色或字体排印。

本决策扩展了 [slot 身份标准](../architecture/2026-07-22-slot-type-chain-implementation.zh.md)，并保持 [工作区浏览归属](2026-07-25-session-list-browsing-and-manual-order.zh.md) 不变。两者均未被取代。

## 备选方案

**在覆盖层内再渲染一次侧边栏。** 这会复制已挂载的工作区区域及其 window 监听器；相同的 slot 键并不能让两个 React 位置变成同一个实例。

**扩展窄屏网格轨道。** 这会在每次导航手势时挤压并重排对话区，而不是保留阅读区域。

**把抽屉做成模态对话框。** 导航不需要阻止键盘访问对话区。在没有真正焦点隔离的情况下声明 `aria-modal` 会错误描述交互，而强行困住焦点又会不必要地改变交互。

## 影响

框架负责导航定位，当侧边栏变为绝对定位时必须保留显式的网格坐标。侧边栏内的草稿在抽屉切换期间保留其所属实例。CSS 使用已有的覆盖层和阴影 token。在非常窄的宽度下，抽屉受包含轨道的网格区域和框架约束；不会持久化额外的宽布局偏好。

布局测试覆盖未改变的轨道宽度、唯一存活的侧边栏元素、占用者宽度、焦点、Escape、遮罩关闭以及桌面偏好恢复。针对现有 GUI 的只读 Playwright 探测在 900px 下验证打开和关闭，只出现一个输入框而不是重复的一对。这些检查并不能证明 Cowork、Design、artifacts、云端执行或调度功能已经完成。
