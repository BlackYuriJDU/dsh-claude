# @deepseek-ai/dsh-client-ui-routines

[English](README.md) | 中文

例行任务插件：定期执行的计划任务。一个例行任务是 durable 的 `ui-routines` 设置条目，包含提示词、以 N 分钟、小时或天为单位的间隔、启用标志以及可选的工作区 cwd。Node 侧注册该命名空间，并运行一个为每个已启用任务设置一个定时器的调度器。每次触发都会通过 `ctx.agents` 以默认模型选择创建一个新的 Agent，把提示词作为普通用户消息提交，等待其静止，dispose（资源释放）该 Agent，并记录 `lastRunAt`。浏览器侧在设置中新增 **Routines** 分节，用于创建、启停、编辑和删除例行任务。

调度器在启动时以及该设置分节每次变化时，根据分节重建定时器。例行任务在上次运行结束后经过一个间隔再触发，且绝不与自身重叠；Host 停机期间间隔已到期的任务会在下次启动时触发一次，而不会补跑所有错过的运行。从未运行过的任务在保存后经过一个间隔触发。定时器均调用 `unref`，因此等待中的任务不会让 Host 进程保持存活。

## 模型体验

### 例行任务提示词

#### 模型看到的内容

每次触发都会开启一个新会话，其第一条用户消息就是该任务存储的提示词文本，插件来源为 `@deepseek-ai/dsh-client-ui-routines`。该会话使用部署的默认 agent（智能体）组合和默认模型运行；若任务设置了工作区，cwd 即为该工作区。

#### Token 影响

每次触发一条用户消息，大小取决于存储的提示词；请求的其余部分是新会话的普通提示词。

#### KV Cache 影响

每次触发都是新会话中独立的模型请求序列；它既不会扩展也不会使任何其他会话的前缀失效。

## 已知限制与暂缓事项

- **不支持 cron 表达式**：间隔固定为 N 分钟、小时或天；无法表达“工作日 09:00”之类的日历计划。
- **不补跑错过的运行**：停机期间到期的所有间隔会合并为下次启动时的一次触发。
- **不展示结果**：一次触发会在会话列表中留下一个会话，但不会发送通知，失败的触发只记录在 Host 日志中。
